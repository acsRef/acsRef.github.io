场景测试（小功能与细节）

单条用例回答“命中了吗”；场景回答工程问题：增量更新会不会重复、删了会不会还召回、跨库会不会串。

场景验证什么步骤
增量更新（同一文档覆盖）
rag-incremental-upsert
同一 document_id 重新上传：文档数不增长、新内容可召回、旧内容被替换v1 入库 → v1 可召回 → v2 入库 → 覆盖而非新增 → v2 新内容可召回 → v1 旧内容已被替换
删除后无脏召回
rag-delete-no-dirty-recall
删文档后：列表清空、检索不再返回该文档内容入库 → 删除前可召回 → 删除接口返回成功 → 文档列表已清空 → 删除后无脏召回
权限：知识库可见性（越权读）
rag-permission-visibility
普通用户读 internal 库必须 403、读 public 库必须 200（拒绝要显式，不能静默空结果）internal 库入库 → 普通用户读 internal 库 → 403 → 普通用户读 public 库 → 200
权限：越权写（建库/上传/删除）
rag-permission-mutations
普通用户没有 kb.create / doc.upload / doc.delete：三个写操作都必须 403，且数据不变admin 入库 → 普通用户建库 → 403 → 普通用户向他人 KB 上传 → 403 → 普通用户删他人文档 → 403 → 数据未被改动
跨库隔离（pin kb_ids）
rag-kb-isolation
指定别的知识库检索时，不得返回本库文档（防跨库污染）临时库入库 → 本库可召回 → pin 其他库时不串本库文档

风险案例库

ReportAgent 精选真实事故（来自 plan 与测试）+ ragent 从题目元数据自动派生（避开 LLM 裁判）。

误答 (2)

ID场景触发条件现有护栏
RA-R1口径被换：问「销售额」答成「净销售额」候选用 `sorted(known_metrics)[:3]`，中文码点把「净」排在「销」前`match_metric_terms` 原话命中优先 + 夹具逐字取口径
EV-R3判定器自己的口径错：2/3 召回永远判 fail阈值写 `ratio >= 0.67`，而 2/3 = 0.6666…，文案却写「至少 2/3」阈值改真分数 `CROSS_DOC_RECALL_MIN = 2/3` + 回归测试 `test_recall_two_of_three_passes`

错误执行 (3)

ID场景触发条件现有护栏
RA-R2过滤写进 LEFT JOIN 的 ON 子句 = 静默不过滤`region='华南'`/`year=2026` 写在 ON，结果算出全库 9.38 亿（真值 3936 万）必需过滤必须在 WHERE；缺失/落 ON 直接进 repair
EV-R1清理临时库把全库删了（14 份文档 / 1391 chunks）`GET /documents` 不支持 `kb_id` 过滤，admin 拿到全库；清理按列出的文档逐个删`ragent_docs` 客户端过滤 + 回归测试；清理只作用于本库 document_id
EV-R5提速开关的隐性代价：关掉元数据 LLM → `chunks.year` 全 NULL为了把入库从分钟级压到秒级设 `INGEST_METADATA_ENABLED=0`平台量化该项代价；重灌必须显式选择档位，并写明「检索可用、元数据加成缺失」

不可追溯 (2)

ID场景触发条件现有护栏
RA-R3失败没有现场：崩了只留 phase=generating内存缓冲导致 span 丢失、`last_failed_action` 为空、report_version 0 行启动孤儿收敛 + span 增量落盘 + `interrupted` 可重试
EV-R2工具超时被当成产品失败（90s 等不到 indexed 就判 fail）PDF 走 OCR（250 页）+ 元数据 LLM 批处理，真实耗时分钟级；批量灌库时串行排队更久等待上限 300s；超时记 `timeout` / verdict `error`，与 `fail` 分开

越权 (2)

ID场景触发条件现有护栏

EV-R4金标证据不成立：问「金额单位」的金标关键词是员工人数标注时把「命中同一份文档」当成「证据成立」，关键词与该问无因果关系判定记录保留 expected/observed，人工复核能看见关键词与问题不对应；不改数据让它变绿

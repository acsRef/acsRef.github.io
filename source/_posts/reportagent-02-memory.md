## 记忆的难点不是"存"，是"算不算数"

把对话丢进向量库，是最容易做、也最容易坏的做法。坏在三个地方：什么话都记（噪声）、记多久说不清（污染）、两句话冲突时谁赢（一致性）。

所以这套记忆有四个存储、四种生命周期，和**一道准入闸**。

![ReportAgent 记忆分层](/img/diagrams/agent-memory.svg)

## 一、四层，各管一件事

| 层 | 存什么 | 生命周期 |
|---|---|---|
| `long_term_memory` | 稳定偏好与业务事实 | 无限期，用户级 |
| `semantic_entry` | 候选队列 + 会话级偏好 | 会话 TTL（24h） |
| `query_template` | 成功 SQL + 向量 | 随访问热度衰减 |
| `conversations` | 多轮转录 | 追加式，不改写 |

分层的判据是**"这句话多久还算数"**，不是"这句话重不重要"。

## 二、准入闸：这句话配不配进库

写入前两道确定性检查：

**闸 1 — 范围与期限**（靠措辞，不靠模型）

| 用户说法 | 判定 | 存到哪 |
|---|---|---|
| 「以后/默认/每次都用柱状图」 | 长期 | `long_term_memory`，无期限 |
| 「这次/先/暂时用表格」 | 会话 | `semantic_entry`，24h |
| 没有任何时间标记 | 不确定 | 候选队列，等证据 |

**闸 2 — 反例拦截**

| 不记 | 为什么 |
|---|---|
| 「给我看华东的销售额」 | 任务参数，不是偏好 |
| 「按刚才那样再来一次」 | 指示引用，没有独立语义 |
| 「这个数对不对？」 | 问句，不是陈述 |
| 太短的碎片 | 信息熵不足 |

这一层的意义在于：**记忆系统的坏，多半不是"忘了"，而是"记错了"。** 宁可不记。

## 三、`memory_key` 是意图槽位，不是内容 hash

这是这张表最关键的设计。唯一键是 `(user_id, memory_key)`，而 `memory_key` 长这样：

```
pref:chart          （图表偏好）
pref:chart:exclude  （图表排除——否定语义单独一个槽）
pref:granularity    （时间粒度偏好）
fact:<内容指纹>     （业务事实）
```

带来的好处是结构性的：

- **同一维度不可能存在两条矛盾偏好**——因为物理上只有一行，冲突写法走 UPSERT 覆盖（`revision+1`，旧值留在 `previous_content`）；
- **否定和肯定不打架**——「以后不要用柱状图」写 `pref:chart:exclude`，不会覆盖「以后都用饼图」。

第二条是踩坑换来的：早期两个写法共用一个槽，结果「不要柱状图」把「用饼图」顶掉了，`pie → bar`，意图直接反转。

## 四、证据晋级：推断可以升级，但到不了 high

模型推断出来的"事实"（用户没说，但从多次交互里看出来的）不能直接当事实用。规则是：

- 同一条说法被观察到 **≥3 次** → 晋级为 active；
- 但 confidence **封顶 `medium`**；
- `high` 永远只留给用户明确说出口的那句。

**判定从热路径移出去**：晋级、过期、同维度收敛全部由每日跑批完成（CLI，带 `--dry-run`），用候选队列 + `promoted_at` 保证幂等与断点续跑。在线路径只做读写，不做判定。

## 五、那次被数据否掉的设计

最初的想法很自然：**用 embedding 相似度自动合并同义记忆**。两条记忆余弦相似度高 → 合并。

先测了一下。真 embedding（Qwen3 系列）上，三类关系的相似度分布：

| 关系 | 例子 | 相似度区间 |
|---|---|---|
| 同义（该合并） | 「净销售额是扣退款后的口径」/「净销售额等于销售额减掉退款」 | 0.695 – 0.933 |
| 不同的事（不该合并） | 「净销售额是扣退款后的口径」/「实收金额是实际到账的口径」 | 0.642 – **0.950** |
| **相反说法**（绝对不能合并） | 「净销售额包含退款」/「净销售额不包含退款」 | **0.906 – 0.962** |

**三类完全重叠。** 「相反说法」的下界（0.906）比「同义」的上界（0.933）几乎一样高。取 θ=0.90 时，一批 26 对样本上出现 7 个错误合并、8 个错误拆分。

结论：**单靠余弦不可行，不是阈值没调好，是这个信号本身不够。**

改成**结构优先判定器**，按顺序判：

```
极性（否定词）→ 数字 → 原子值冲突 → 原子值一致 → 灰区复审 → 否则 distinct
```

| 判定 | 依据 |
|---|---|
| 极性不同 → `opposite` | 否定词表（单一真源，与报告层共用） |
| 数字不同 → `distinct` | 抽出的数字集合不交 |
| 原子值冲突 → `distinct` | 指标/维度/粒度/图表类型任一不同 |
| 原子值一致 → `merge` | 所有原子都对得上 |
| 灰区（相似度 ≥0.90 但原子无冲突） | **不合并**，进 `merge_candidate` 待人工复审 |

同一批 26 对实测：**错误合并 0，精确率 1.00，召回 0.92**。

一句话总结这段：**当你打算用相似度做判断时，先去量一下"你不想合并的那类东西"的相似度是多少。** 如果两者重叠，换信号，别调阈值。

## 六、召回排序：档位优先，热度只能打破平局

召回不是简单按相似度排。真实问题是：**语义相似度高但不可信的记忆**（比如一条只看过一次的候选）会压掉**语义稍低但确定是用户说的**记忆。

所以排序键是 `(档位, 辅助分)`，档位宽 0.05（约等于 0.083 的相似度）。LFU/LRU 只在**同一档内**打破平局。

这个设计也被数据验证过：早期让热度权重直接参与排序，退化测试里 R@3 从 **96% 掉到 56%**（10 条本该召回的被热度更高的挤掉）。改成档位后回到 **92%**。

## 七、实测

| 指标 | 值 |
|---|---|
| R@1 | **0.840** |
| R@3 | **0.960** |
| MRR | **0.900** |
| Clean（不该召回时确实没召回） | **1.000** |

评测集：25 条记忆 × 30 条金标查询，真 embedding。

## 小结

记忆系统只有四个真问题：**记什么（准入）、记多久（生命周期）、冲突谁赢（槽位 + UPSERT）、推断算不算数（证据晋级）**。

剩下的都是实现细节。而"用相似度自动合并"这种看起来很聪明的做法，值得先用数据打自己一巴掌再决定。
